# OpenI 多任务笛卡尔积训练设计

## 目标

扩展统一入口 `train_openi.py`，使 `--model` 和 `--dataset` 接受逗号分隔数组，并在单个启智训练任务中顺序执行模型与数据集的笛卡尔积。单模型、单数据集用法保持兼容。

## 命令行接口

示例：

```text
--model DLinear,PatchTST \
--dataset ETTh1,Weather \
--pred-len 96,192 \
--batch-size 96:128,192:64
```

该命令按以下顺序生成四个任务：

1. `DLinear × ETTh1`
2. `DLinear × Weather`
3. `PatchTST × ETTh1`
4. `PatchTST × Weather`

模型和数据集数组分别去重并保留输入顺序。名称继续支持现有大小写不敏感与别名解析。

## 任务矩阵与预检查

入口先解析完整笛卡尔积，并在启动任何 baseline 子进程前检查：

- 每个模型和数据集名称有效；
- 每个模型/数据集组合已在任务注册表中声明支持；
- 每个组合支持显式选择的全部预测长度；
- 所有组合需要的数据文件均存在；
- 全局 batch size 映射完整且合法。

任何预检查失败时，入口输出清晰错误并返回退出码 2，不启动任何 GPU 训练。以 `TimeMixer` 和 `ILI` 组成的矩阵会因不支持该组合而整体拒绝。

代码仓库解析、数据集路径解析和任务参数校验在执行循环之前完成。启智 `c2net` 上下文只初始化一次，产物只在整个入口结束时统一上传一次。

## 预测长度语义

显式传入 `--pred-len 96,192` 时，列表必须对笛卡尔积中的每个任务都有效；任何一个任务不支持其中的长度，整个矩阵预检查失败。

未传 `--pred-len` 或传入 `all` 时，每个任务使用自身的标准预测长度：

- 普通数据集：`96,192,336,720`；
- ILI：`24,36,48,60`。

预测长度仍按用户输入顺序执行；`all` 使用任务注册表中的标准顺序。

## 全局 Batch Size 映射

`--batch-size` 继续使用 `pred_len:batch_size` 格式，并对矩阵中的全部任务生效。同一个预测长度在所有模型和数据集上使用相同 batch size。

显式预测长度示例：

```text
--pred-len 96,192 --batch-size 96:128,192:64
```

当 `all` 同时包含普通数据集和 ILI 时，映射必须覆盖整个矩阵实际预测长度的并集：

```text
--batch-size 24:64,36:64,48:32,60:32,96:128,192:64,336:32,720:16
```

完成全局映射校验后，每个任务只接收其实际预测长度对应的子映射。未传 `--batch-size` 时，每个 baseline 保持自身默认 batch size。

## 执行与失败隔离

任务矩阵在单 GPU 上严格串行执行，不并发启动模型或预测长度。

入口对每个模型/数据集组合调用现有 `run_task()`：

- 一个预测长度失败后，该任务继续运行剩余预测长度；
- 一个模型/数据集任务失败后，入口继续运行矩阵中的剩余任务；
- 只要任意任务失败，整个入口最终返回非零退出码；
- 已有 `status=succeeded` 的预测长度继续支持自动跳过；
- `--force` 对矩阵中的全部任务生效。

运行时异常记录在对应模型/数据集/预测长度目录中，不影响其他任务的输出路径。

## 输出与汇总

现有任务产物结构保持不变：

```text
<output_path>/<model>/<dataset>/<pred_len>/
```

每个模型/数据集目录继续生成现有 `metrics_summary.json`、`metrics_summary.csv` 和 `status_summary.json`。

输出根目录新增：

```text
multi_task_summary.json
multi_task_summary.csv
```

汇总按任务矩阵和预测长度执行顺序记录：

- `model`
- `dataset`
- `pred_len`
- `status`
- `task_exit_code`

JSON 额外包含整体 `exit_code` 和任务级结果。CSV 每行对应一个模型/数据集/预测长度。Dry-run 同样构建完整矩阵，标准输出 JSON 返回所有任务的状态和原生命令，但不写训练状态文件。

## 组件边界

- `registry.py`：解析逗号列表、构造并验证任务笛卡尔积；
- `train_openi.py`：完成全局预检查、顺序编排、整体退出码与上传；
- `runner.py`：继续负责单个模型/数据集及其预测长度，不承担矩阵逻辑；
- `openi_baselines/matrix.py`：定义矩阵任务计划和 `MatrixResult`，把多个 `RunResult` 归一化为根目录 JSON/CSV，避免继续增大 CLI 文件。

## 测试

自动化测试覆盖：

- 单模型、单数据集参数向后兼容；
- 模型和数据集列表的解析、去重与顺序；
- 笛卡尔积生成顺序；
- 不支持组合在训练前整体失败；
- 显式预测长度对所有任务严格校验；
- `all` 下普通数据集和 ILI 使用各自 horizon；
- 全局 batch size 对预测长度并集的校验和按任务过滤；
- 多任务严格串行执行；
- 单任务失败后继续后续任务并返回整体非零退出码；
- 根目录 JSON/CSV 汇总顺序与内容；
- dry-run 返回完整任务矩阵且不启动子进程。

## 非目标

- 不并行执行多个模型、数据集或预测长度；
- 不支持按位置配对模型与数据集；
- 不为不同模型/数据集设置不同 batch size；
- 不自动跳过不支持的任务组合或预测长度；
- 不自动探测显存或动态调整 batch size；
- 不改变现有 baseline 原生命令和模型实现。
