# OpenI 按预测长度配置 Batch Size 设计

## 目标

为统一入口 `train_openi.py` 增加按 `pred_len` 一一指定 batch size 的能力，使同一训练任务中的不同预测长度可以使用不同显存配置，同时保持未传参数时的 baseline 原始默认值不变。

## 命令行接口

新增可选参数 `--batch-size`，采用 `pred_len:batch_size` 逗号分隔映射：

```text
--pred-len 96,192,336,720 \
--batch-size 96:128,192:96,336:64,720:32
```

启智训练任务继续使用 `train_openi.py` 作为启动文件，不生成新的 Python 启动器。完整参数示例：

```text
--model PatchTST --dataset ETTh1 --pred-len 96,192 --batch-size 96:128,192:64
```

## 解析与校验

未传 `--batch-size` 时，所有模型继续使用仓库原有的模型/数据集默认 batch size。

传入 `--batch-size` 时执行严格校验：

- 每个已选择的 `pred_len` 必须且只能出现一次；
- 不允许映射未选择或当前任务不支持的 `pred_len`；
- batch size 必须是正整数；
- 空项、缺少冒号、非整数、重复预测长度均在训练开始前报错；
- 映射顺序不影响执行顺序，预测长度仍按 `--pred-len` 的顺序执行。

解析结果使用 `dict[int, int]` 表示，并在任务进入 runner 前完成验证。

## 命令构建与执行

runner 在处理每个预测长度时取出该长度对应的 batch size，并传给原生命令构建器。构建器只在存在覆盖值时替换或补充 `--batch_size`；不存在覆盖值时维持当前命令不变。

所有标准单阶段 baseline 都使用该预测长度的覆盖值。ST-MTM 的预训练和微调两个阶段同时使用同一个覆盖值，保证该预测长度任务内部配置一致。

不同预测长度仍然顺序执行，因此 batch size 映射不会造成多个 horizon 同时占用显存。

## 产物与错误处理

最终原生命令已经由现有 `command.json` 记录，因此实际使用的 `--batch_size` 会随任务产物保存，无需增加新的产物格式。

参数校验失败时，入口返回退出码 2，并在启动任何 baseline 子进程前输出清晰错误信息。单个预测长度训练阶段的失败行为、续跑和产物上传逻辑保持不变。

## 测试

自动化测试覆盖：

- 合法的单个和多个映射；
- 映射顺序与 `pred_len` 顺序无关；
- 缺失、额外、重复、非整数和非正数映射；
- 单阶段 baseline 的 `--batch_size` 覆盖；
- 原本没有显式 batch size 的 baseline 能正确补充覆盖值；
- ST-MTM 预训练和微调同时覆盖；
- 未传参数时现有 79 个模型/数据集任务的命令保持兼容；
- CLI 在启动 runner 前拒绝非法映射。

## 非目标

- 不自动探测显存或动态搜索 batch size；
- 不并行执行多个预测长度；
- 不修改 epoch、学习率或梯度累积；
- 不生成新的 `.py` 或 `.sh` 启动器；
- 不改变未传 `--batch-size` 时的 baseline 默认超参数。
